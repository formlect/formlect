#### Implementation strategies

Option A: The "Middleware" (Zapier / Make.com)
If you want to save development time, don't build every integration yourself.

How it works: You provide a "Webhook URL" field in your FormSchema. When a submission happens, your server sends a POST request to that URL.

Pros: The user can connect to 5,000+ apps without you writing a single line of Notion-specific code.

Two patterns
1. Transactional outbox pattern - for critical data like form submission, we can use transactional outbox pattern to ensure data consistency and reliability. This way, even if there is a failure in the integration process, we won't lose any data.
2. Sweeper pattern - for non-critical data, we can use sweeper pattern to periodically check for new data and process it. This way, we can avoid the overhead of maintaining a queue and worker for every integration.
